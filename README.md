# 流变·孪生 · dsh-liubian-twin

> 在同一个会话里挂一名**监察智能体**。它不看最终答案，而是在每个动作**发生之前**用会话自己的模型审一遍；偏离用户指令就当场拦下，并把可直接执行的纠正交回给模型。

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的插件。与 `dsh-liubian`（流变·记忆）功能上不互通，只在命名上同属流变系列。

## 为什么检查点要放在"动作发生之前"

事后审查的方案不少见：等模型写完一整段回答，再打分、再重写。问题是那时候**动作已经发生了**——文件改了、命令跑了、请求发了。此时拦截，等于用一次昂贵的返工去换一个本可以避免的后果。

孪生把检查点前移到「动作即将落地」的那一瞬间，而且它是**阻塞式**的：审查期间执行侧零产出，不存在"边审边输出"。代价是回答不再逐字流式（思考流 → 停顿 → 整段出现），收益是偏离在造成后果之前被按住。

监察**不改写**执行侧的输出，也不接管它的工作——只给结论、证据，以及"下一步改成什么"。

## 两个闸门

| 闸门 | 挂在哪 | 拦住的是什么 | 判为偏离时 |
|---|---|---|---|
| 工具闸门 | `tools/pre-execute` | 工具**尚未派发** | 拒绝：工具不执行，模型收到纠正文本，被迫改道 |
| 文本闸门 | 包裹 `llm/stream` | 该步文本**尚未放行** | 原文整块丢弃；改为合成一次内部工具调用，用它的结果把纠正回给模型 |

两者都只做一件事：把"要不要放行"这个判断插到动作与后果之间。判断本身交给会话自己的模型——不额外配置 API key，也没有独立的模型开关。

## 一次审查的生命周期

1. **抽样**：不是每一步都审，按下一节的规则挑；
2. **组装送审上下文**：最近若干轮对话**拍平成普通文本**（清掉全角竖线、思考阶段标记这类特殊标识符），附上用户原话、被审动作、判据；
3. **调用**：用会话自己的 provider / model 发一次**不带工具**的请求；
4. **解析**：回复的第一行必须是结论词——`通过` 或 `纠正`；
5. **回流**：通过则原样放行；纠正则走拒绝或合成调用，模型在同一步内重写。

送审请求的末尾会追加一条"思考已结束"的助手消息，把生成位从"续写执行侧的对话"挪到"直接给这份结论"——否则模型倾向于接着执行侧的活干下去，而不是当裁判。

## 什么时候审

| 规则 | 含义 |
|---|---|
| 链首 / 类型切换 | 该动作与上一个动作不同类（比如从工具调用切到输出正文）→ 必审 |
| 次数间隔 | 距上一次审查 ≥ N 次动作 → 审 |
| 时间间隔 | 距上一次审查 ≥ N 分钟 → 审 |
| 预算 | 每回合最多审 N 次，用尽后静默跳过 |
| 未解决出口 | 同一回合提过两次意见后停止继续审，避免死循环 |

抽样不是为了省钱，是为了**信噪比**：全审会让每个动作都拖进一次模型往返，用户会感到每步都在停顿。设计取值时的参考数据：8 个真实会话、3267 次工具动作，工具调用覆盖率约 10.6%，每回合约 3 次审查。

## 判据（criteria.json）

判据与角色、输出契约一起定义"什么算偏离"。插件自带一份，格式如下：

```json
{
  "version": 1,
  "role": "……监察智能体的角色与规矩……",
  "contract": "第一行只写「通过」或「纠正」，第二行起写理由，合计不超过 300 字……",
  "usage": "下面每一条都是用来检查被审动作的，按 when 对场景取用。",
  "items": [
    { "id": 1, "when": "每一步。",
      "q": "要求这一步能说出它对应的是用户说过的哪句话；说不出来的算偏离。" },
    { "id": 45, "when": "动作是在反驳用户。",
      "q": "要求它先给出理由：结论有没有证据支持、证据够不够；给不出就先核实或标成待核实，不要为了反驳而反驳。" }
  ]
}
```

条目按 `when` 描述的场景取用，场景对不上的跳过。覆盖面大致是：**是否对应用户原话**、**有没有多做**（新文件/依赖/流程）、**有没有证据**（结论、数字、引用、"已验证"）、**结论强度是否过头**（少量样本、只在一个环境试过）、**不可逆动作**（定稿、批量写、删除、覆盖）、**越界**（别人的文件、正在用的东西）、**实验纪律**、**工程纪律**（凭据、临时补丁、遗留进程）。

想改措辞不必动代码：把覆盖文件放到 `~/.dsh/liubian-twin/criteria.json`，它优先于插件自带那份。

## 配置

写在 `~/.dsh/liubian-twin/config.json`（不存在就全用下面的默认值）。

```jsonc
{
  // 触发
  "twinChainHeadAlways": true,    // 链首 / 类型切换必审
  "twinGapCalls": 10,             // 距上次审查 ≥ N 次动作
  "twinGapMinutes": 10,           // 距上次审查 ≥ N 分钟
  "twinMaxReviewsPerTurn": 12,    // 每回合审查预算

  // 送审上下文
  "twinContextMode": "flatten",   // flatten（拍平）| isolated（只带最近一条）| full（整段原样）
  "twinTranscriptRounds": 10,     // 拍平最近多少轮
  "twinIncludeTools": false,      // 工具调用与结果不进背景
  "twinIncludeReasoning": true,   // 模型思考进背景
  "twinPrompt": "",               // 追加的自定义要求

  // 超时与失败
  "twinIdleTimeoutMs": 5000,      // 两次输出之间空档多久算超时（不掐思考耗时）
  "twinTimeoutMs": 300000,        // 单次审查绝对上限
  "twinRetryDelayMs": 5000,       // 失败重试间隔
  "twinRetryMax": 5,              // 重试次数

  // 记录
  "twinRecordInSession": false,   // 审查记录是否写进会话（默认只落 jsonl）
  "twinRecordThinking": false,    // 思考全文是否进上下文（默认只留占位标记）
  "twinRecordChars": 1200,        // 开启上面那项时的截断长度
  "twinUnavailableText": "监察api不可用，请尝试关闭插件或者稍后尝试"
}
```

**监察不可用时会怎样**：工具闸门逐条拒掉（模型只看到上面那句固定文本，什么都执行不了），并中断回合；文本闸门放行原文、末尾补同一句申明。持续失败最坏会把回合冻住约 25 秒（5 秒 × 5 次重试）再中断——这是"宁可停住，也不放行一个不可逆动作"的固有代价。

**审查记录去哪了**：每次审查的思考全文与裁决都写在 `~/.dsh/liubian-twin/sessions/<sessionId>.jsonl`。默认**不写进会话**：一来审查记录随每轮请求重发会推高上下文，二来它落在 step 边界之外会让宿主的压缩失败。要在对话里看到它，把 `twinRecordInSession` 设为 `true`。

## 与流变·记忆的边界

`dsh-liubian` 负责记忆，`dsh-liubian-twin` 负责监督，两者**不引对方的代码、不读对方的数据**。监察需要的历史材料（接入卡、教训块、能力卡）本来就作为会话消息存在，从会话里原样取即可，因此没有任何耦合。

孪生**没有独立开关**：停用 / 卸载本插件即停用孪生，记忆注入完全不受影响。

## 它实际抓到了什么（实测）

统计自插件自己的审查记录（`~/.dsh/liubian-twin/sessions/<sessionId>.jsonl`，用 `_dev/twin_review_stats.cjs` 可随时复算）：截至 2026-09-19，6 个真实会话累计 **160 次审查**，判偏离 **80 次**（这个数字会随使用继续增长）。把这 80 条判偏离的理由逐条过了一遍，形态集中在六类（每条都能在记录里按时间查到）：

| 类别 | 典型形态 |
|---|---|
| 把没核实的东西写成结论 | 数字没有出处；"说得像已确认、但依据不完整"；"已验证"其实只是一条推理链 |
| 答非所问 | 用户问 A、动作去做 B；把内部产物（裁决文本、章节编号、行号）原样端给用户 |
| 替用户改了范围 | 用户没要求的实验组、没交办的新文件、用户说过"不用重做"的那一组也重跑 |
| 命令本身有缺陷 | 在派发之前拦下：未转义的引号会截断 PowerShell 字符串这类必然失败的命令 |
| 证据自相矛盾 | 同一动作里两处数字对不上；引用了本轮根本没读过的文件 |
| 凭据位置不当 | 明文密码写进命令行参数（会被作业日志记录下来） |

这些不是理论收益，而是**同模型**监察在这条流水线上实际拦下的东西。它起作用的机制不是"换了个更聪明的模型"，而是：只看一个动作、手里有判据表、不必接着往下干活。

## 已知限制

1. **判偏离是监察的判断，不是真值**：它也会判错、也可能拦得过头。防线是三条机制——每回合审查预算、同一回合提过两次意见后停审、角色里强制要求引用证据。
2. **停等语义**：回答不再逐字流式，每回合会有几次可感知的停顿。
3. **长任务拦不住**：一个跑很久的工具调用开始之后，最早的检查点是它返回之后。
4. **最坏冻结**：监察 API 持续失败时，回合会在约 25 秒后被中断。

## 安装

把仓库放进 DSH 的插件目录（或交给插件加载器加载）。插件自带 bundle 元数据，装配后重启 DSH 生效。

## 开发

```bash
node --check lib/impl.mjs
node _dev/stub_test.mjs     # 28 项桩测：判据 / 指令拼装 / 裁决解析 / 触发规则 / 文本闸门五契约 / 工具闸门 / 送监形态
node _dev/gate_sim.mjs      # 触发规则在真实会话上的复算与对账
node _dev/meter_check.cjs   # 用宿主 token-meter 的规则重放会话日志（排查"压缩失败"这类问题）
node _dev/twin_review_stats.cjs  # 统计审查记录：通过 / 判偏离，并逐条列出判偏离理由
```

改 `lib/impl.mjs` 后热注入即生效（入口壳用带时间戳的动态导入绕开 ESM 模块缓存）；改 `name` / `inject` 需要重启。
